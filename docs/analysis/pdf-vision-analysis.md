# 첨부 PDF의 Vision 분석 (보류)

- 기준일: 2026-08-31
- 상태: **보류. 구현하지 않는다.** 조건이 관측되면 켠다 — 조건은 5절
- 본 설계: [PDF 첨부 파싱·BM25 색인](pdf-parsing-bm25.md)
- 입력 계약: [문서 본문·첨부 수집](../collection/document-body-collection.md)

로컬 추출로 글자가 안 나오는 영역(스캔 페이지, 격자가 무너진 표, 그림 안에만 값이 있는
차트)을 외부 Vision 모델에 보내 텍스트로 바꾸는 설계다. **2026-08-31에 1단계 범위에서
뺐다.**

**왜 뺐나.** 검색이 BM25 하나이고, 우리 첨부 PDF는 대부분 디지털 발행이라 로컬 추출
(`page.get_text()`)이 이미 본문·표 셀·차트 라벨의 글자를 다 준다. 표 구조도
`find_tables().extract()`가 로컬로 만든다. **Vision이 유일하게 더하는 것은 텍스트 레이어가
아예 없는 페이지의 글자인데, 그 페이지가 몇 %인지 재 본 적이 없다.** 0에 가까우면 dispatcher
DAG·프롬프트 판·원장 테이블·게이트 상수 여섯을 만들고 글자는 하나도 못 늘린다.

**이 문서를 지우지 않는 이유.** 조건이 관측되면 그대로 구현하면 되는 계약이고, 게이트·상한·
원장·모델 선택은 다시 만들려면 같은 조사를 반복해야 한다.

## 1. 외부 분석 후보 판정

### 1.1 이미지형 페이지

기본 후보 규칙은 다음과 같다. 값은 운영 설정이 아니라 파서 모듈의 상수로 시작하고, 실제 NAS
운영 지표를 근거로만 바꾼다.

**아래 두 숫자는 아직 재 본 적이 없는 잠정값이다.** 백필 대상 PDF 772건이 이미 NAS에 있으므로
파싱 설계 10절 3단계에서 후보 통계를 먼저 뽑고 그 분포로 확정한다. 근거 없는 상수를 그대로 두면
이 문서의 다른 숫자(0.5GB·772건 등)와 달리 출처가 없는 값이 하나 남는다.

```text
visible_chars < 80
and min(sum(image_bbox_area / page_area), 1.0) >= 0.20
    => kind=image_page
```

가장 큰 이미지 하나의 면적만 사용하지 않는다. 작은 이미지 조각 여러 개가 페이지 전체 내용을
구성할 수 있기 때문이다. `image_page`는 페이지 전체를 렌더링한다.

### 1.2 표

한 페이지의 벡터 도형은 한 번만 읽는다.

```python
drawings = page.get_drawings()
tables = page.find_tables(paths=drawings).tables
```

**`paths` 파라미터는 PyMuPDF 1.26에서 생겼다**(1.25.5에 없고 1.26.0에 있다, 2026-08-31 실측).
그보다 낮은 버전에서는 `find_tables()`가 내부에서 `get_drawings()`를 다시 돌아 페이지당 가장
비싼 호출이 두 번이 된다. 그래서 버전 하한이 `>=1.26`이다.

`find_tables()` 결과는 구조화 데이터로 확정하지 않고 표 영역을 찾는 데만 쓴다. 각 표 bbox의
로컬 텍스트와 렌더링 이미지를 외부 요청에 함께 넣는다.

### 1.3 차트

표 탐지에서 읽은 `drawings`를 다시 사용한다.

```python
regions = page.cluster_drawings(drawings=drawings)
```

너무 작거나 페이지 전체에 가까운 영역은 버린다. 표 bbox와 겹치는 차트 후보는 중복 요청하지
않고 더 구체적인 표 후보를 우선한다.

### 1.4 중복 제거

동일한 첨부·페이지에서 겹치는 bbox는 하나로 합친다. 렌더링한 결과의 SHA-256이 이미 처리된
크롭과 같으면 새 외부 요청을 만들지 않는다.

## 2. 가치 판정 — 부르기 전에 거른다

1절이 만든 것은 "여기 표가 있다"까지다. **그 표에 값이 있는지는 아직 모른다.** 크롭 하나가
외부 호출 하나이므로, 로고·머리글·장식 도형·빈 격자를 그대로 보내면 비용의 대부분이 아무
것도 아닌 그림에 나간다. 리포트 PDF는 표지·목차·면책 문구 페이지를 늘 갖고, 회사 로고는
모든 쪽에 있다.

**판정은 모델이 하지 않는다.** 값을 내는 것은 모델이고 판정은 코드다 — 모델이 판정까지 하면
틀렸을 때 나눌 자리가 "모델이 틀렸다" 하나뿐이다. 여기 쓰는 값은 파싱이 읽는 것들이다:
단어 좌표, `get_drawings()`의 도형, `get_image_info()`의 면적, 렌더한 픽스맵. **이 중 좌표·도형·
렌더링은 파싱 설계가 1단계에서 뺐으므로, 이 문서를 켤 때 파서에 함께 되살린다.**
**새 의존성도 새 모델 호출도 없다.**

### 2.1 게이트 다섯

순서대로 보고 **하나라도 걸리면 그 자리에서 확정하고 이유를 남긴다.** 점수 하나로 합치지
않는다 — 합치면 왜 걸렀는지가 사라지고, 임계를 어느 쪽으로 옮겨야 하는지도 모른다.

| 게이트 | 거르는 것 | 신호 |
| --- | --- | --- |
| 1 크기 | 아이콘, 구분선, 페이지 장식 | bbox의 짧은 변이 `MIN_CROP_SIDE_PT` 미만이거나 면적이 페이지의 `MIN_CROP_AREA_RATIO` 미만 |
| 2 반복 | 로고, 머리글·바닥글, 워터마크 | 같은 첨부에서 같은 `crop_sha256`이 두 쪽 이상, 또는 같은 위치의 bbox가 페이지 수의 절반 이상에서 반복 |
| 3 잉크 | 빈 상자, 단색 배경, 장식 띠 | 렌더한 크롭의 비백색 픽셀 비율이 `MIN_INK_RATIO` 미만이거나, 고유색이 `MIN_COLORS` 미만이면서 bbox 안 단어가 0개 |
| 4 로컬로 이미 읽힘 | **호출할 이유가 없는 표** | 2.2 |
| 5 값 없음 | 숫자도 라벨도 없는 그림 | bbox 안 단어가 0개이고 도형이 `MIN_DRAWINGS` 미만 |

통과한 것만 3절의 외부 요청이 된다. `image_page`는 게이트 1·2·3만 본다 — 페이지 전체가
대상이라 크기는 늘 통과하고, 4·5는 "텍스트가 거의 없다"가 이미 후보 조건(1.1)이라 다시
물을 것이 없다.

**픽셀 통계는 이미 렌더한 픽스맵에서 뽑는다.** 게이트 때문에 따로 렌더하지 않는다. 게이트
1·2는 렌더 전에 좌표만으로 판정되므로 **거기서 걸린 크롭은 아예 그리지 않는다** — 디스크와
CPU가 그만큼 안 든다.

### 2.2 표는 로컬로 끝나는 것이 기본이다

증권사 리포트와 중앙은행 PDF는 대부분 벡터 PDF다. 표 셀에 텍스트 레이어가 그대로 있고
`find_tables()`가 격자를 이미 알고 있다.

```python
grid = tables[i].extract()   # 행 × 열 문자열
```

- 격자의 **채움률**(빈 문자열이 아닌 셀 / 전체 셀)이 `MIN_TABLE_FILL` 이상이고
- 행이 둘 이상, 열이 둘 이상이며
- 숫자로 읽히는 셀이 하나라도 있으면

**그 표는 로컬로 확정하고 외부로 보내지 않는다.** 병합에는 격자를 편 텍스트가 들어간다.

1.2가 "구조화 데이터로 확정하지 않는다"고 한 것은 **격자 판정을 무조건 믿지 않는다**는
뜻이었다. 믿지 않는 것과 쓰지 않는 것은 다르다. 채움률이 임계를 넘으면 그 격자는 이미
사람이 읽을 수 있는 표이고, 그것을 그림으로 다시 그려 모델에게 읽히는 것은 같은 값을 두 번
사는 일이다. 격자가 성기거나 병합 셀로 무너진 표만 외부로 간다.

**스캔 PDF는 여기서 자동으로 갈린다** — 텍스트 레이어가 없어 채움률이 0이고, 그래서 외부로
간다. 이 설계가 NAS에 OCR을 두지 않고도 스캔 문서를 처리하는 경로가 이것이다.

### 2.3 애매한 것은 버리지 않고 센다

- 게이트에 걸린 요청은 `skipped`로 확정하되 **어느 게이트인지 함께 남긴다**
  (`skip_reason=gate_ink` 등). 임계를 옮겼을 때 무엇이 다시 들어오는지 그 이유로 센다.
- **분모를 함께 올린다.** 후보 총수, 게이트별로 걸린 수, 남아서 실제로 부른 수 셋을 태스크가
  로그가 아니라 값으로 올린다. 분모 없는 카운터는 카운터가 아니다.
- **임계 언저리는 따로 표시한다.** 각 게이트의 임계에서 20% 안쪽으로 걸린 것은
  `skipped(borderline)`으로 남긴다. 조용히 버리는 것과 다르고, 임계를 다시 정할 때 이 집합만
  다시 그려 보면 된다.
- 모델이 `has_value=false`로 답한 수(4.5)와 이 게이트들이 거른 수를 함께 본다. 모델이 자주
  "값 없음"을 답하면 게이트가 느슨하다는 뜻이고, 반대로 걸린 것 중에 값이 있었다는 것은
  이 수로는 안 보인다 — 그래서 `borderline` 집합이 필요하다.

### 2.4 잠정 상수

**전부 아직 재 본 적이 없는 값이다.** 파싱 설계 10절 3단계가 실측으로 확정한다.

| 상수 | 잠정값 | 무엇을 겨냥하나 |
| --- | ---: | --- |
| `MIN_CROP_SIDE_PT` | 60 | 아이콘·구분선 |
| `MIN_CROP_AREA_RATIO` | 0.02 | 페이지 장식 |
| `MIN_INK_RATIO` | 0.02 | 빈 상자·여백 |
| `MIN_COLORS` | 8 | 단색 로고 |
| `MIN_DRAWINGS` | 20 | 도형 몇 개짜리 장식 |
| `MIN_TABLE_FILL` | 0.6 | 로컬로 읽히는 표의 하한 |

값은 파서 모듈의 상수다. 운영 설정으로 빼지 않는다 — 값이 바뀌면 무엇이 다시 들어오는지
재처리 판정에 걸리므로 파서 버전과 함께 움직여야 한다(파싱 설계 6.1).

## 3. 외부 요청 계약

파싱 단계는 다음 매니페스트까지만 만든다. **부르는 것은 4절의 dispatcher다.**

```json
{
  "request_id": "ext-001",
  "document_id": 0,
  "attachment_id": 0,
  "source_sha256": "...",
  "page": 1,
  "kind": "table|chart|image_page",
  "bbox_pdf_points": [0.0, 0.0, 595.3, 841.9],
  "crop_path": "...",
  "crop_sha256": "...",
  "local_text": "...",
  "status": "not_called",
  "skip_reason": null,
  "parser_version": "..."
}
```

상태는 여섯이고 **누가 바꾸는지가 정해져 있다.**

| 상태 | 뜻 | 누가 |
| --- | --- | --- |
| `not_called` | 부를 차례를 기다린다 | 파서가 만든다 |
| `skipped` | 게이트가 걸렀다. `skip_reason`이 어느 게이트인지 갖는다 | 파서(2절) |
| `done` | 외부 결과를 받아 병합했다 | dispatcher |
| `no_value` | 모델이 값이 없다고 답했다(`has_value=false`) | dispatcher |
| `failed` | 호출이나 검증이 실패했다. 원인을 함께 남긴다 | dispatcher |
| `deferred` | 상한에 걸려 미뤘다. 다음 실행이 다시 집는다 | dispatcher |

필수 규칙은 다음과 같다.

- 파싱 태스크는 외부 API 키를 읽지 않는다. 네트워크 클라이언트도 없다.
- 매니페스트와 로그에 API 키를 저장하지 않는다.
- **호출 여부를 매니페스트의 플래그로 두지 않는다.** 켜고 끄는 것은 4.6의 상수 하나이고,
  플래그를 행마다 두면 켤 때 전 행을 UPDATE해야 한다.
- 응답 병합 전에 현재 첨부 SHA와 `source_sha256`을 다시 비교한다.
- 모델명·프롬프트 판·토큰·비용은 매니페스트가 아니라 **원장**이 갖는다(4.7). 매니페스트는
  "무엇을 물을 것인가"이고 원장은 "무엇을 물었나"다.
- 문서 중요도와 재시도 정책은 dispatcher가 담당한다.

### 3.1 크롭과 매니페스트를 두는 자리

첨부 파일이 이미 `documents/<출처>/<문서ID>/<순서>.<확장자>`에 있다
([문서 본문·첨부 수집](../collection/document-body-collection.md) 7.2). 파싱 산출물도 같은 폴더에
두고 이름만 나눈다. DB에는 뿌리(`/opt/airflow/files`)를 뺀 상대경로만 남기는 규칙이 그대로다.

```
documents/boj/1042/0.pdf              원본 첨부
documents/boj/1042/0.parse.json       파싱 매니페스트(페이지·단어·이미지·외부 요청)
documents/boj/1042/0-p3-table-1.png   크롭
```

**새 볼륨이 필요 없다.** `airflow/files`는 로컬·운영 compose 양쪽에 이미 마운트되어 있다
(`${AIRFLOW_PROJ_DIR}/files:/opt/airflow/files`).

**크롭은 원본 PDF와 bbox로 언제든 다시 만들 수 있다.** 144 DPI A4 한 장이 대략 1~3MB이므로
후보가 페이지의 30%만 돼도 크롭 총량이 원본 PDF(백필 0.5GB)를 넘는다. **호출이 확정된
크롭은 지운다**(4.6). 확정 전에는 남겨 두어 재시도가 다시 렌더하지 않게 한다.

## 4. 외부 호출 — dispatcher

파서는 크롭과 매니페스트까지 만들고 끝난다. 부르는 것은 **별도 DAG**이고, 그 코드는
저장소의 다른 LLM 흐름과 같은 모양이다(`.claude/skills/writing-llm-flows`).

### 4.1 DAG 둘

| DAG | 하는 일 | 스케줄 | 실패 판정 |
| --- | --- | --- | --- |
| `document_attachment_parse_hourly` | 로컬 파싱, 후보·가치 판정, 크롭, 매니페스트 | `20 * * * *` | 항목별 실패 수집. **전부 실패일 때만 죽인다** |
| `document_attachment_vision_hourly` | 매니페스트를 읽어 Vision 호출, 결과 병합 | `40 * * * *` | 같음 |

분 단위 cron이라 시간대가 값을 바꾸지 않는다. DAG의 `start_date`는 다른 DAG와 같이
`pendulum.datetime(..., tz=KST_TIMEZONE)`으로 둔다.

- 둘 다 **다음 시간이 같은 큐를 다시 본다.** 하나가 실패했다고 죽이면 경보만 늘고 고쳐지는
  것이 없다 — `document_ingestion_hourly`와 같은 판정이고 근거는 각 DAG의 모듈 docstring
  "실패와 재시도" 절에 남긴다.
- 큐는 상태가 정한다. 파싱은 파싱 상태가 `NULL`인 첨부, 호출은 `not_called`인 요청이다.
- **`document_body_hourly` 뒤에 선다.** 첨부 파일이 있어야 파싱할 것이 있다.
- 파싱만 pool `pdf_parse`(슬롯 1)에 넣는다. 호출 DAG은 CPU를 안 쓰므로 그 pool을 물지 않는다
  — 물리면 NAS의 파싱 한 슬롯이 네트워크 대기에 잡힌다.
- 둘 다 `dag_display_name`·`description`·`doc_md`를 채운다(저장소 규칙). 이름은
  `📄 첨부 PDF 파싱`, `🖼 첨부 표·차트 분석 (Vision)`이다.

### 4.2 그래프

**크롭 하나가 요청 하나다.** 바깥 그래프가 `Send`로 크롭마다 안쪽 그래프를 부르고
(`modules/assessment.py`의 팬아웃과 같은 모양), 안쪽은 저장소의 표준 호출–교정이다.

```python
graph.add_node("call", self._call)
graph.add_node("repair", self._repair)
graph.add_edge(START, "call")
graph.add_conditional_edges("call", self._next, {"repair": "repair", END: END})
graph.add_edge("repair", "call")
```

`_call`이 묻고 **검증까지 한다.** `_next`는 첫 시도에서만 `repair`로 보낸다 — 교정은 한
번이고 재시도는 Airflow가 한다. 호출이 하나뿐이어도 그래프를 갖는다: `if`로 교정을 쓰면
트레이스에 이름 없는 모델 호출만 남는다.

흐름은 컴파일된 그래프를 소유한 클래스가 갖는다(`AttachmentVisionAnalyzer`). 생성자는 연결과
모델과 상한처럼 **그 실행 동안 안 변하는 것**만 받고, 크롭은 메서드 인자다.

### 4.3 모델

`modules/llm.py`에 `attachment_vision_model()`을 더한다. **어떤 모델을 쓸지는 코드가 정하고
바꿀 때 이 함수 하나를 고친다** — `base_url`이나 모델명을 환경변수로 빼지 않는다.

```python
def attachment_vision_model() -> BaseChatModel:
    return ChatOpenAI(
        model="gpt-5.6-luna",
        timeout=REQUEST_TIMEOUT_SECONDS,
        max_retries=0,
    )
```

- 문서 태깅(`document_model`)과 **같은 모델·같은 키**(`OPENAI_API_KEY`)다. 키를 새로 발급하지
  않고, `langchain-openai`가 이미 이미지에 있어 의존성도 늘지 않는다.
- **이 모델이 우리 크롭(한글 리포트 표, 중앙은행 차트)을 읽는지는 아직 재지 않았다.**
  이 문서를 켤 때 **프로토타입이 먼저다** — 실제 크롭 20~30장을 스크래치패드에서 태워
  출력을 사람이 보고 확정한다. 재 보지 않고 켜지 않는다.
- 재시도는 Airflow가 한다(`max_retries=0`). 타임아웃은 문서 태깅과 같은 300초로 시작한다 —
  이미지 한 장에 툴 왕복이 없다.

#### 왜 이 모델인가 (2026-08-31 조회)

값싼 Vision 후보를 공급사 가격표로 대조했다. 크롭 하나를 1000×700px, 프롬프트 400토큰,
출력 400토큰으로 잡고 계산한 값이다. OpenAI는 32px 패치 × 1.2배(704패치 → 845토큰),
Gemini는 768px 타일당 258토큰(2타일 → 516토큰)으로 이미지를 센다.

| 모델 | 입력·출력 $/1M | 크롭 1건 | 크롭 5,000건 |
| --- | --- | ---: | ---: |
| Gemini 2.5 Flash-Lite | 0.10 / 0.40 | $0.00025 | $1.3 |
| **gpt-5.6-luna** | 0.20 / 1.20 | **$0.00073** | **$3.7** |
| Gemini 3.1 Flash-Lite | 0.25 / 1.50 | $0.00083 | $4.2 |
| Gemini 3.5 Flash-Lite | 0.30 / 2.50 | $0.00127 | $2.4 |
| Gemini 3.x Flash | 0.75 / 3.75 | $0.0022 | $11 |

**루나보다 싼 것은 Gemini 2.5 Flash-Lite 하나인데 2026-10-16 이후 퇴역 예정이다.** 새로
붙일 수 없다. 그 위의 Gemini는 전부 루나보다 비싸므로, **값으로 고르면 루나가 남는다**
(사용자 결정 2026-08-31).

정확도는 남의 벤치에서 갈린다. Roboflow Vision Evals(같은 표본·6과제, 2026-08 기준)에서
데이터 추출이 Gemini 3.5 Flash-Lite 90.7%, 루나 81.4%이고 OCR은 88.4%(루나) 대 87.4%로
사실상 같다. 문서 파싱 전용 벤치(ParseBench)도 표·차트에서 Gemini 쪽이 낫다는 방향이다.
**그 차이가 우리 문서에서도 나는지는 확인되지 않았다** — 벤치 표본이 한글 증권사 리포트가
아니다. 그래서 프로토타입이 먼저다.

**옮길 때의 조건과 비용도 미리 적어 둔다.** 프로토타입이나 운영에서 표 전사가 무너지면
다음 후보는 Gemini 3.1 Flash-Lite이고, 옮기는 값은 크롭 5,000건에 $0.5쯤 더 드는 것이
아니라 **`langchain-google-genai` 의존성 하나와 새 API 키, 그리고 운영 이미지 재빌드**다.
PyMuPDF를 넣느라 재빌드를 어차피 한 번 하므로(파싱 설계 10절 1단계), 옮길 생각이 있으면 **그 재빌드에
함께 얹는 것이 가장 싸다.**

전체 규모가 월 몇 달러라 가격 차이가 판단을 뒤집지 못한다는 것도 함께 적어 둔다 — 제일 싼
후보와 제일 비싼 후보의 백필 1회 차이가 $10 미만이다. 그래서 **다음에 이 줄을 고칠 근거는
가격이 아니라 프로토타입과 운영 지표(`has_value=false` 비율, 병합 실패 수)여야 한다.**

이미지는 LangChain 표준 콘텐츠 블록으로 싣는다. 크롭 PNG를 base64 data URI로 넣고, **같은
메시지에 로컬 텍스트와 페이지 번호를 함께 준다** — 표 제목이나 단위가 bbox 밖에 있는 경우가
흔하고, 그림만 주면 모델이 그것을 지어낸다.

### 4.4 프롬프트

`modules/prompts/attachment_vision.yaml` 하나다. `system`·`instruction`·`repair` 세 칸이고
치환은 `string.Template`(`$이름`), 빠진 값은 실패다. 종류(`table`·`chart`·`image_page`)는
자리표시자로 들어가고 파일 하나 안에서 갈라 쓴다.

**판을 둔다.** `VISION_PROMPT_VERSION`이 코드 상수이고 `tests/modules/test_prompt_versions.py`의
해시 잠금 표에 넣는다. 이 문장이 병합 본문을 만들고 재처리 판정이 그 판을 보므로, 문장만
고치고 판을 안 올리면 서로 다른 프롬프트의 결과가 한 본문에 섞인다.

숫자 상한을 YAML에 적지 않는다. 코드 상수가 원본이고 자리표시자로 들어간다.

### 4.5 응답 모양

Pydantic 모델에서 JSON Schema를 뽑아 `response_format`으로 강제하고 **검증은 그대로 남긴다.**
제공처가 스키마를 못 받으면 `llm.classify`가 `UnsupportedResponseFormat`으로 바꾸고 스키마
없이 한 번 더 부른다 — 그 자리가 이미 있다.

```json
{
  "has_value": true,
  "title": "...",
  "text": "...",
  "units": "...",
  "period": "...",
  "caveats": "..."
}
```

- **`has_value=false`가 정상 답이다.** 게이트가 못 거른 장식 그림을 거르는 마지막 자리이고,
  그 수를 따로 센다(2.3). 억지로 채우지 말라고 프롬프트가 명시한다.
- `table`은 열 이름·단위·행을, `chart`는 제목·축·범례·기간·주요 값과 추세를, `image_page`는
  페이지 본문을 `text`에 담는다.
- **표는 Markdown 표로 쓴다**(헤더 줄 + 구분선). 2.2가 로컬로 확정한 표도 같은 형식으로
  편다 — 둘이 병합 본문의 같은 자리에 들어가므로, 형식이 갈리면 한 문서 안에 표가 두 모양
  으로 섞인다. 그 본문이 그대로 BM25 색인과 LLM 프롬프트로 가므로 표기가 갈리면 검색어와
  읽는 쪽이 둘 다 흔들린다. 단위는 열 이름에 괄호로 붙이고 `units`에도 그대로 남긴다.
- **투자 조언·목표가·앞으로의 방향 예측을 쓰지 않는다.** 이 금지는 프롬프트와 **저장 전
  검증 둘 다**에 둔다. 프롬프트에만 있는 금지는 가드레일이 아니다 — 어겼는지도 모른다.
- 값을 **지어내지 않는다.** 읽을 수 없으면 그 칸을 비우고 `caveats`에 이유를 쓴다. 빈 칸은
  병합에서 그대로 빈 칸이고, 그것이 지어낸 숫자보다 낫다.

### 4.6 상한과 손잡이

셋 다 코드 상수다.

| 상수 | 잠정값 | 무엇을 막나 |
| --- | ---: | --- |
| `MAX_VISION_CALLS_PER_RUN` | 100 | 한 실행이 쓰는 비용. 큐가 밀려도 실행당 지출이 정해진다 |
| `MAX_VISION_CALLS_PER_ATTACHMENT` | 30 | 표가 200개인 PDF 하나가 예산을 다 먹는 것 |
| `MAX_VISION_CALLS_PER_DAY` | 1,000 | 하루 지출. 원장(4.7)을 세어 판정한다 |

**잠정값의 근거는 4.3의 크롭 단가 $0.00073이다.** 시간당 100건이면 하루 2,400건이 되지만
일일 상한이 1,000에서 잘라 **하루 $0.73, 한 달 최악 $22**로 묶인다. 백필 대상(크롭 5,000건
가정)은 그 속도로 닷새다. 정상 유입은 리포트 하루 40건 규모라 상한 근처에 가지 않는다.
**실제 크롭 수는 파싱 설계 10절 3단계가 세고, 그때 이 셋을 확정한다.**

- **`MAX_VISION_CALLS_PER_RUN = 0`이 곧 기능 끄기다.** 되돌리기 비용이 상수 하나이고, 이것이
  이 기능의 유일한 손잡이다. 카나리나 비율 롤아웃은 쓰지 않는다 — 하루 처리량이 그것을 가를
  만큼 많지 않다.
- **상한에 걸린 요청은 `not_called`로 남긴다.** 버리지 않고 다음 실행이 집는다. 그 수를
  올리므로 큐가 계속 밀리는지 보인다.
- 호출이 확정된(`done`·`no_value`) 크롭 파일은 지운다. 원본 PDF와 bbox로 언제든 다시 그릴 수
  있고, 남겨 두면 크롭 총량이 원본 PDF를 넘는다(3.1).

### 4.7 원장

**호출 하나가 행 하나다**(`document_vision_run`). 모델을 부르기 **전에 별도 트랜잭션으로
커밋**하고 끝에서 닫는다. 실패 경로도 반드시 닫고 예외는 다시 올린다. 행조차 안 생기면
"안 돌았다"와 "돌다 죽었다"를 못 가른다.

남기는 칸: `attachment_id`·`page`·`kind`·`crop_sha256` / 모델명 / 프롬프트 판 / `dag_run_id`·
`try_number` / `started_at`·`finished_at` / 상태·오류 / 입력·출력 토큰 / `has_value` /
교정 재요청 여부. `thesis_llm_run`이 같은 모양이고 그 테이블을 베낀다.

**트레이스는 원장의 대체물이 아니다.** 켜졌을 때만 있고 보존 기간이 우리 것이 아니며 SQL로
조인할 수 없다.

### 4.8 오류

`llm.classify`가 제공처 예외를 재시도할 값어치가 있는 것(`RetryableLlmError`)과 없는 것
(`LlmError`)으로 이미 가른다. **중간 층은 예외를 통과시킨다** — 문자열로 뭉개면 DAG가 판단할
것을 잃는다. `document_assessment_hourly`가 배치 노드에서 정확히 그렇게 판단을 잃은 적이 있다.

- 되돌릴 수 없는 것(인증, 4xx, 스키마 거절 뒤에도 실패)은 DAG가 `AirflowFailException`으로
  바꾼다.
- 재시도할 값어치가 있는 것은 그대로 올려 Airflow가 재시도한다.
- 크롭 하나의 실패는 그 요청만 `failed`로 두고 나머지를 계속한다. **전부 실패면 태스크를
  죽인다.**

### 4.9 조용한 성공을 만들지 않는다

매 실행이 아래를 **값으로** 올린다. `logger.warning`은 세는 것이 아니다.

| 세는 것 | 없으면 안 보이는 것 |
| --- | --- |
| 후보 수 / 게이트별 컷 수 / 실제 호출 수 | 게이트가 너무 조인지 느슨한지 |
| 요청 수 / 응답 수 | 조용히 빠진 크롭 |
| `has_value=false` 수 | 게이트가 놓친 장식 그림의 양 |
| 교정 재요청 수 | 첫 답이 얼마나 자주 못 쓰는가 |
| 상한에 걸려 미룬 수 | 큐가 밀리는지 |
| 병합 실패 수 | 결과가 있는데 본문에 안 붙는 경우 |

**대기 큐가 남아 있는데 호출도 컷도 0이면 성공으로 끝내지 않는다.** 그것은 큐를 못 읽었거나
상한이 0인데 아무도 모르는 상태다.

### 4.10 밖으로 나가는 것

- 모델 호출은 **첨부의 일부(크롭 이미지와 그 주변 텍스트)를 제공처로 보내는 일**이다. 수집
  대상이 중앙은행·감독기관·증권사가 공개한 문서라 이 설계는 그것을 허용 범위로 본다.
  비공개 문서를 수집하게 되면 이 줄부터 다시 본다.
- `LANGSMITH_*`를 켜면 **프롬프트와 크롭 이미지가 LangSmith로 나간다.** 켤지는 그 사실을 알고
  정한다.
- API 키는 LangChain 클래스가 자기 이름으로 읽는다. 우리가 설정 객체나 그래프 상태에 담지
  않는다 — 상태와 config는 트레이스 입력으로 나간다.

### 4.11 기준선과 접는 조건

- **기준선은 로컬 텍스트만으로 만든 색인이다.** Vision을 켠 뒤 검색 결과와 리포트 입력이
  그보다 나아지지 않으면 켤 이유가 없다.
- 접는 조건 셋: ① `has_value=false` 비율이 높으면 게이트(2절)를 먼저 조인다. ② 병합 결과가
  로컬 텍스트에 없던 값을 못 주면 `MAX_VISION_CALLS_PER_RUN=0`으로 끈다. ③ 호출당 비용이
  4.6의 일일 상한을 계속 물면 대상 종류를 줄인다(먼저 `chart`를 끈다 — 표보다 값이 성기다).
- **모델은 안전하게, 관측 가능하게, 가드레일 안에서, 계속 쓸모없을 수 있다.** 그래서 접는
  조건을 켜기 전에 적는다.

### 4.12 공급사 Batch API는 지금 쓰지 않는다

**"배치"가 두 가지를 가리킨다.** 하나는 4.2의 팬아웃 — 한 태스크가 크롭 여럿을 `Send`로
도는 것이고, 이 설계가 쓰는 방식이다(사용자 결정 2026-08-31). 다른 하나는 공급사의 Batch
API(JSONL을 올리고 24시간 안에 받는 대신 요금이 절반)이고, **그것은 쓰지 않는다.**

- 절감액이 백필 1회 기준 $2 안팎이다(4.3의 단가). 월 정상분은 그보다 작다.
- **LangChain에 그 경로가 없다.** `.batch()`는 클라이언트 병렬일 뿐 할인 배치가 아니다.
  진짜 Batch API를 쓰면 JSONL 조립·업로드·폴링·수거를 직접 짜게 되고, 그 순간 호출–교정
  그래프도 LangSmith 추적도 `response_format` 경로도 우리가 다시 만든다. 저장소 규칙이
  금지하는 "HTTP를 직접 치는 흐름"이 하나 생긴다.
- DAG이 제출·폴링·수거 셋으로 늘고, 24시간 비동기라 부분 결과와 재개를 새로 설계해야 한다.
  그동안 그 첨부는 색인 대기로 묶인다.

**다시 볼 조건**: 파싱 설계 10절 3단계 실측에서 크롭이 5만 건을 넘거나(백필이 $35 이상), 동기 호출이
rate limit에 걸리면 그때 옮긴다. 그 시점에는 절감액이 복잡도를 넘는다.

## 5. 켜는 조건

**둘 중 하나가 관측되면 켠다.** 파싱 설계 10절 3단계의 실측이 첫째를 답한다.

1. **텍스트 레이어가 없는 페이지가 유의미하게 나온다.** 그 문서들은 지금 검색에 아예 없다.
   판정은 페이지당 `visible_chars` 분포로 하고, 기준은 파싱 설계 4.3과 같다.
2. **market-thesis가 첨부를 근거로 읽을 때 표가 깨져 틀린 값을 인용하는 것이 관측된다.**
   격자가 무너진 표(파싱 설계 4.2의 채움률 미달)가 그 자리다.

**둘 다 관측으로 판정한다.** 문서에 임계를 적어 두고 사람이 기억하는 방식은 쓰지 않는다.

켤 때는 이 문서의 1~4절을 그대로 구현하고, 파싱 설계의 저장 계약(6절)에 요청 상태와 원장을
더한다. 켠 뒤에도 **호출 상한 0이 기능 끄기**라는 성질(4.6)은 그대로다.
