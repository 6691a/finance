- 이전본: 2026-08-11 승인본
- 상태: **1·2단계 구현 완료, 3·4단계 재계획 보류.** 2단계는 `document_ingestion_hourly`(수집)와
  `document_assessment_hourly`(LLM 태깅) 둘로 갈려 운영 중이다. 청크·임베딩은 아직
  없다(6.4의 벡터 판정 절이 그렇다). **본문과 첨부 수집은
  [collection/document-body-collection.md](../collection/document-body-collection.md)가 계약을
  갖는다**(2026-08-30 구현 완료, 배포 대기) — 그 문서 4절이 여기 `content_hash` 정의를 바꿨다.
  해시는 이제 제목과 요약만 본다.
  3·4단계는 market-thesis가 사실상 같은 자리를
  채우고 있어 착수 전에 범위를 다시 잡는다 — 7·8절 머리에 그 표기가 있다

## 0. 왜 다시 쓰는가

이전본은 **사람이 검색창에 단어를 치는 것**을 목적으로 썼다. BM25와 vector를 RRF로 합쳐
순위를 매기고, 가치가 낮은 문서는 보류함으로 보내 사람 눈에서 치우는 설계였다.

실제 목적은 그게 아니다. 모은 기사와 시세를 **LLM에게 먹여 시장 리포트를 만드는 것**이다.
소비자가 사람이 아니라 LLM이면 세 가지가 달라진다.

- 검색 UI가 필요 없다. 리포트를 만들 때 문서를 고르는 축은 단어가 아니라 **기간과 태그**다.
- 문서를 버릴 이유가 없다. 사람은 다 못 읽지만 LLM은 프롬프트에서 상위 N개만 고르면 된다.
  보류함은 나중에 기준을 바꿀 때 되돌릴 수 없는 손실만 만든다.
- **기사에 종목·지표가 조인 가능한 형태로 붙어 있어야 한다.** 이게 이전본에서 가장 크게
  빠진 부분이다. 자유 문자열 `entities`로는 `instrument`와 조인이 안 된다.

## 1. 최종 목적

지금까지 모은 시세·수급·금리·공시에 기사를 더해, LLM이 시장 상황을 서술한 리포트를 남긴다.

목표로 하는 문장은 이런 모양이다.

> USDKRW와 005930의 20일 수익률 상관이 −0.62로 지난달 −0.31에서 강해졌다. 같은 기간
> 외국인은 5거래일 연속 순매도했고, 반도체 업황 기사 세 건이 감산 계획을 다뤘다.

**여기서 −0.62를 계산하는 것은 LLM이 아니다.** SQL이 계산해서 값으로 주고, LLM은 그 값을
문장으로 옮기고 기사와 엮는다. 이 경계를 지키지 않으면 리포트는 데이터를 보지 않고도
그럴듯하게 들리는 글이 된다.

## 2. 단계

| 단계 | 내용 | LLM |
| --- | --- | --- |
| 1 | Yahoo 일봉 수집 | 없음 |
| 2 | **기사 수집 + LLM 태깅·점수 → 저장** (지금 구현 대상) | 있음 |
| 3 | 일별 요약 테이블 | 없음 |

목적이고 2단계가 그 입력을 만든다.

## 3. 제외 범위

- 검색 API, BM25/vector 순위 결합(RRF), 검색 필터 — 4단계에서 문서 검색이 실제로 필요해지면
- 문서 상태 머신과 보류함 — 전부 저장하고 점수만 남긴다
- 과거 문서 백필, OCR이 필요한 스캔 PDF
- 이미지·음성·영상 분석
- 기사 번역, 자동 요약 서비스, 자연어 질의응답
- Elasticsearch, OpenSearch, 별도 vector DB
- ~~LangGraph, LLM 에이전트, LangSmith~~ — **2026-08-16에 셋 다 들어왔다.** 흐름 제어는
  `StateGraph`이고(`modules/assessment.py`), 툴을 쥔 에이전트는 market-thesis가 만들었으며,
  추적은 `LANGSMITH_*` 환경변수로 켠다. 이 줄은 2026-08-15 시점의 판단이었고 지금은 거짓이다.
  호출 수 상한이 있는 고정 파이프라인이라는 원칙 자체는 살아 있다 — 상한이 `MAX_TOOL_CALLS`다
- LLM이 직접 쓰는 SQL. 계산은 애플리케이션이 구현한 종류만 실행한다(§8.2)
- 외부 공개 또는 상용 재배포

필요가 확인되기 전까지 이 범위는 추가하지 않는다.

## 4. 이 저장소의 제약

설계를 쓰기 전에 실제 저장소가 어떤 상태인지 못 박는다. 이전본은 여기서 네 군데가 틀렸다.

**스키마를 쓰지 않는다.** `apps/core/database.py`의 `table_options`에는 `schema` 인자가 없고,
모든 테이블이 연결의 `search_path`(`public`)를 따른다. 실제 DB의 테이블 스무 개가 전부
`public`에 있다. 이 문서에서 `content.document` 같은 표기를 쓰지 않는다.

**Airflow 의존성은 `compose/local/airflow/requirements.txt`가 정한다.** 이미지가 빌드에서
설치하고 운영도 같은 파일을 쓴다. **이 설계를 위해 늘린 의존성은 없다.**

- ~~LLM 호출은 `urllib.request`로 충분하다~~ — **2026-08-16에 폐기됐다.** 지금은 LangChain의
  `BaseChatModel`을 쓴다(`modules/llm.py`의 `document_model()`·`thesis_model()`·
  `expectation_model()`). HTTP를 직접 치면 LangSmith 추적이 끊기고 툴 호출 왕복을 직접 짜야
  한다. **`base_url`을 환경변수로 빼 제공처를 갈아 끼우지도 않는다** — 어떤 모델을 쓸지는
  코드가 정하고 API 키만 환경에서 온다. 그것도 LangChain 클래스가 자기 이름
  (`XAI_API_KEY`·`OPENAI_API_KEY`)으로 읽는다.
- RSS·Atom은 `xml.etree.ElementTree`가, RFC 822 날짜는 `email.utils.parsedate_to_datetime`이
  읽는다. `feedparser`가 필요 없다.
- 문서 분할(`langchain-text-splitters`)은 임베딩과 함께 붙일 때 넣는다. **아직 없다** —
  `document_chunk` 테이블도 HNSW 인덱스도 0건이다.
- PDF 본문 추출(`pypdf`)은 아직 범위 밖이다.

노트북과 배포가 같은 코드를 쓴다는 성질은 그대로다. `notebooks/narrator_ab.ipynb`가
`modules/llm.py`의 모델 팩토리를 그대로 import한다.

**DAG는 `config.yaml`을 읽지 못한다.** 원본 저장소 루트는 `config.yaml`이 아니라 Airflow
환경변수 `DOCUMENT_ARCHIVE_PATH`로 준다. 값이 없으면 태스크를 즉시 실패시킨다.

**ParadeDB 문법은 버전을 탄다.** 개발·운영 모두 `paradedb/paradedb:0.25.2-pg17`이다.
`pg_search`는 `shared_preload_libraries`에 있어야 `CREATE EXTENSION`이 된다. 그리고
`pdb.lindera(korean)`은 **인덱스 토크나이저 이름이 아니라 컬럼에 씌우는 캐스트다.**
0.25.2에서 실제로 도는 형태는 다음과 같다.

```sql
CREATE INDEX document_bm25 ON document
USING bm25 (id, (body::pdb.lindera('korean'))) WITH (key_field='id');

SELECT id FROM document WHERE body @@@ '기준금리';
```

ParadeDB는 0.2x 사이에서 이 API를 바꿔 왔다. 버전을 함께 적지 않은 문법은 몇 달 뒤 틀린다.

**OpenDART는 이미 수집 중이다.** `dart_disclosure_intraday`가 삼성전자·SK하이닉스 공시를
2분마다 `disclosure_event`에 넣는다. 이 아카이브는 OpenDART를 다시 받지 않는다. 공시가
리포트 입력으로 필요하면 `disclosure_event`를 직접 읽는다.

## 5. 1단계 — Yahoo 일봉 수집

`yahoo.py`는 지금 1분봉만 받는다. 1분봉은 제공처 보존이 30일이라 그 이상 쌓이지 않는다.
일봉에는 그 제한이 없고 **심볼당 요청 한 번에 10년치가 온다.**

- `quote_symbol`에 등록된 심볼마다 `interval=1d`로 받는다. 요청은 심볼 수만큼이다.
- 새 테이블 `quote_daily(provider, symbol, business_date, open, high, low, close, volume,
  source_record_id)`에 넣는다. 자연키는 `(provider, symbol, business_date)`다.
- **`quote_bar`에 합치지 않는다.** 분봉은 `bar_at` timestamptz가 축이고 일봉은 날짜가 축이다.
  보존 정책도 다르다. 한 테이블에 섞으면 모든 조회가 봉 종류를 걸러야 한다.
- 국내 종목 일봉은 이미 `stock_investor_trade_daily`에 시가·고가·저가·종가가 있다.
  중복 수집하지 않는다.

3단계와 4단계의 상관 계산이 이 테이블 위에서 돈다.

수집 주기는 1시간이다. RSS는 최근 항목만 주므로 **수집을 시작하기 전 기간은 영영 비어 있다.**
출처를 늘리는 것보다 시작을 앞당기는 쪽이 값이 크다.

### 6.2 데이터 모델

`source_record`는 그대로 재사용한다. 크롤링 문서 버전 하나가 레코드 하나이며 `source_type`은
`crawl`, API 출처는 `api`다. 작은 RSS·API JSON은 `payload`에, 큰 원본은 파일 저장소에 두고
`payload_uri`와 SHA-256만 남긴다. API 키와 인증 헤더는 어디에도 남기지 않는다.

새 테이블은 다섯이다.

**`document_source`** — 출처 카탈로그와 수집 정책.

`slug`(자연키), `name`, `source_kind`(`official`·`media`), `country`(ISO 3166-1 alpha-2,
국제 출처는 `NULL`), `collection_mode`(`metadata_only`·`feed_content`·`full_text`),
`terms_url`, `terms_checked_at`, `enabled`.

**`document`** — 문서 한 건의 정규화 결과와 LLM 평가.

`source_record_id`(`source_record.id` 외래키, `ON DELETE RESTRICT`), `source_slug`,
`external_id`, `canonical_url`, `document_type`(`article`·`report`·`press_release`·`speech`),
`title`, `summary`, `body`, `language`, `published_at`, `detected_at`, `content_level`,
`content_hash`, `canonical_document_id`(중복 대표 문서 자기참조), `direction`, `value_score`,
`assessment`(JSONB), `llm_model`, `prompt_version`, `assessed_content_hash`, `assessed_at`.

- `detected_at`은 우리가 그 문서를 처음 본 시각이다. `published_at`이 없는 출처가 있어
  시간순 정렬의 바닥이 된다.
- `assessed_content_hash`는 **평가한 시점의 본문 해시**다. 지금 `content_hash`와 다르면 본문이
  바뀐 것이라 다시 평가한다. 이 두 칸의 비교가 재평가 판정의 전부다.
- 자연키는 **`(source_slug, external_id)`** 다. 이전본의 `(source_id, external_id, content_hash)`는
  해시가 바뀌면 새 행이 생겨 재수집을 못 막는다. 본문이 바뀌면 같은 행을 갱신하고
  `content_hash`로 재평가 여부를 가른다.
- `external_id`는 필수다. 제공처 ID가 없으면 정규화 URL을 쓴다.
- 컬럼 이름이 `source_id`가 아니라 `source_slug`인 것은 `document_source.slug`를 그대로
  들고 있기 때문이다. 대리키 조인을 한 단 줄인다.
- `status` 컬럼을 두지 않는다. 보류·승인 상태 머신이 없기 때문이다. 중복만
  `canonical_document_id`로 표시한다.
- `value_score`는 저장만 하고 어떤 자동 처리도 하지 않는다. 4단계 프롬프트가 정렬에 쓴다.
- `content_level`이 `metadata_only`인 문서의 `body`는 `NULL`이어야 한다. DB `CHECK`로 막는다.
- 인덱스는 `published_at`, `content_hash`, `canonical_document_id`에 둔다.

**`document_instrument(document_id, ticker)`**, **`document_indicator(document_id, provider,
series_id)`** — 기사와 종목·지표를 잇는 조인 테이블.

**이 두 테이블이 2단계의 핵심 산출물이다.** 4단계 리포트가 "지난 7일 005930 관련 기사"를
뽑는 경로가 여기다. 자유 문자열 태그로는 이 조인이 안 된다. `ticker`는 `instrument`를,
`(provider, series_id)`는 `indicator_series`를 가리킨다.

**외래키는 걸지 않는다.** `indicator_observation`이 `indicator_series`를 참조하지 않는 것과
같은 이유다. 마스터에 없는 값이 오면 수집이 죽는 대신, 그 태그만 버리고 문서는 저장한다.
마스터와의 대조는 테스트가 한다.

**`document_chunk`** — 임베딩 단위. **아직 만들지 않았다**(G-15). 아래는 붙일 때의 설계다.

`document_id`, `position`, `content`, `content_hash`, `embedding`, `embedding_model`,
`embedded_at`. 자연키는 `(document_id, position)`이다.

임베딩 차원은 설정값과 컬럼이 같아야 하고 시작 시 불일치하면 중단한다. **HNSW 인덱스를
함께 만든다.** 인덱스 없이 매시간 유사 후보를 찾으면 문서가 늘수록 배치가 끝나지 않는다.

본문은 `RecursiveCharacterTextSplitter(chunk_size=2000, chunk_overlap=200)`으로 나눈다.
문단 경계를 우선하고 한국어·영어 문장부호를 구분자에 넣는다.

### 6.3 본문 정규화

> **2026-08-30 갱신.** 실제 규칙은
> [collection/document-body-collection.md](../collection/document-body-collection.md) 6절이
> 갖는다. 아래 "해시 안정성" 논리는 **더 이상 본문에 걸리지 않는다** — `content_hash`가
> 제목과 요약만 보므로 본문의 노이즈가 재평가를 부르지 않는다. 정규화는 검색 품질을 위해
> 그대로 한다.

**`content_hash`의 안정성이 여기에 통째로 달려 있다.** 이전본에는 이 절이 없었다. 본문에
조회수나 "3분 전" 같은 상대시각이 섞여 있으면 매시간 새 버전이 생긴다.

정규화 순서를 고정한다.

1. `script`, `style`, `nav`, `footer`, 광고·공유·추천 컨테이너를 제거한다.
2. 상대시각(`3분 전`), 조회수, 공유수, 기자 이메일, 저작권 푸터를 패턴으로 지운다.
3. 연속 공백을 하나로 줄이고 앞뒤를 자른다.
4. 정규화한 본문으로 SHA-256을 만든다.

패턴이 출처마다 다르므로 규칙은 `document_source`가 아니라 출처별 파서가 갖는다. 새 출처를
붙일 때 **같은 문서를 두 번 수집해 해시가 같은지 확인하는 것이 인수 조건이다.**

### 6.4 중복 판정

세 단계로 자른다. LLM은 마지막에만 부른다.

1. 같은 출처의 `external_id`가 이미 있고 `content_hash`도 같으면 아무것도 하지 않는다.
2. 정규화 URL이나 `content_hash`가 같으면 대표 문서에 연결한다.
3. 기사는 발행시각 ±72시간, 보고서는 ±30일에서 vector 후보를 찾는다.
   코사인 **0.95 이상은 규칙으로 중복 처리**, **0.80 미만은 무관으로 버린다.**
   그 사이 구간만 LLM에게 `unique`·`update`·`repeated`·`duplicate`를 묻는다.

임계 0.95와 0.80은 초깃값이다. 첫 2주 분포를 보고 조정한다. 이전본은 후보가 있으면 전부
LLM에 보냈는데, 그러면 비용이 문서 수가 아니라 후보 쌍 수에 비례한다.

`update`는 같은 사건이어도 새 수치·발언·정책이 있으면 별도 문서로 둔다. `repeated`는 중복으로
연결하되 지우지 않는다. 물리 삭제는 제공하지 않는다.

#### 구현 (①② 완료, 2026-08-25)

`airflow/modules/dedup.py`가 ①과 ②를 갖는다. ③(vector·LLM 회색지대)은 미구현이다.

- ①은 upsert가 맡는다. `document/upsert.sql`이 `content_hash`가 같으면 아무것도 쓰지 않는다.
- ②는 `content_hash` 완전일치다. 해시가 제목·요약·본문을 이어 붙인 SHA-256이라 값이 같으면
  셋이 글자 그대로 같고, 그래서 **출처를 걸지 않고 제목도 보지 않는다.** 전재 기사는 제목이
  갈리므로 제목 유사도로는 잡히지 않는 것이 이 규칙의 이유다.
- **정규화 URL 동일 판정은 넣지 않았다.** `document`에 정규화 URL 컬럼이 없고, 같은 URL이면
  본문도 같아 해시가 이미 잡는다. URL만 같고 본문이 달라지는 경우(기사 갱신)는 ③의 `update`
  판정이 할 일이라 여기서 흉내 내지 않는다.
- ②에도 시각 창(±72시간, ③의 기사 창과 같은 값)이 있다. **실측 때문이다**(2026-08-25 운영
  DB, 문서 2,332건): 해시가 겹치는 48묶음 중 출처가 둘 이상인 것은 0이었고, 창이 없으면
  33일에 걸친 BOJ 통계 항목 4건(요약·본문이 비어 제목만 같다)과 6일 간격 KIND 공시 2건이
  한 문서로 묶인다.
- **지금 운영 데이터에서 ②가 새로 잡는 쌍은 0이다.** 출처가 다른 해시 동일 쌍이 전 기간 0건
  이다(연합↔인포맥스는 한쪽만 켜져 있다). 전재가 겹치는 출처를 켜는 순간을 위한 규칙이다.

### 6.5 LLM 출력

모델 호출은 LangChain이 하고(`modules/llm.py`의 `document_model()`), 흐름 제어는
LangGraph가 한다(`modules/assessment.py`의 `AssessmentBatch`·`DocumentAssessor`). 저장은
기존 코드 그대로다.

**어떤 모델을 쓸지는 코드가 정한다.** `LLM_BASE_URL`·`LLM_CHAT_MODEL`을 환경변수로 빼
제공처를 갈아 끼우지 않는다 — 제공처마다 LangChain 클래스와 인자가 달라 문자열 설정 몇
개로 흉내 내면 어느 쪽도 제대로 못 쓴다. **API 키는 우리가 읽지 않는다** — LangChain
클래스가 자기 이름(`OPENAI_API_KEY`·`XAI_API_KEY`)으로 읽는다. 키를 우리 설정 객체에
담으면 로그와 예외에 실릴 자리만 는다.

DAG가 읽는 환경변수는 둘뿐이고 **모델과 무관하다**: `LLM_PERSPECTIVE`(선택, 기본 `global`)와
`LLM_MAX_CONCURRENCY`(선택, 기본 4). DAG는 `config.yaml`을 읽지 못하므로(§4) 여기에 둔다.

### 관점은 값이지 프롬프트가 아니다

**세계에서 일어난 일이 한국 시장에 닿는 경로를 보는 것이 기본이다**(`global`). 미국 금리와
달러, 반도체 업황은 한국을 한 번도 언급하지 않으면서 한국 자산 가격을 움직인다.

관점을 문자열 하나(`PERSPECTIVES`)로 빼고 프롬프트는 한 벌만 둔다. 지역마다 프롬프트를
복사하면 세 벌이 따로 늙는다. 지금 있는 값은 셋이다.

| 값 | 무엇을 보는가 |
| --- | --- |
| `global` (기본) | 세계 문서를 읽고 한국 시장에 닿는 경로까지 |
| `korea` | 국내에서 직접 일어난 일만 |
| `us` | 미국 시장의 눈으로 |

**관점은 `prompt_version`에 함께 저장한다**(지금 `3/global`). 관점이 바뀌면 같은 문서라도 점수가
달라지므로 재평가 대상이 돼야 하는데, 컬럼을 늘리는 대신 기존 재평가 조건(§10)에 얹는다.

**출력은 스키마로 강제한다.** Pydantic 모델을 strict JSON Schema로 바꿔 `response_format`에
싣는다(`modules/schema.py`). 제공처가 받으면 형식이 깨진 응답이 디코딩 단계에서 막혀 아예
오지 않는다. `direction`이나 `confidence` 같은 값도 검증기가 아니라 스키마의 `enum`이 막는다.

strict 모드가 요구하는 것이 둘 있다. 모든 객체에 `additionalProperties: false`가 있어야 하고,
**기본값이 있는 필드도 `required`에 들어가야 한다.** 그리고 `dict[str, float]` 같은 열린
사전은 표현할 수 없어 `{"name": ..., "value": ...}` 배열로 바꿨다. 이 제약이 오히려 낫다 —
키가 자유 문자열이면 그 값을 찾아 쓰는 쪽이 매번 추측해야 한다.

**제공처가 스키마를 못 받으면 스키마 없이 한 번 더 부른다.** 그때는 프롬프트와 사후 검증이
형식을 지킨다. 강제가 되면 좋고, 안 되면 검증이 받는다.

지금 구현된 것은 일곱 키다(`assessment.Assessment`).

```json
{
  "instruments": ["005930"],
  "indicators": [{"provider": "yahoo", "series_id": "USDKRW"}],
  "topics": ["monetary_policy"],
  "direction": "positive | negative | neutral",
  "scores": {"relevance": 0, "novelty": 0, "specificity": 0, "impact": 0},
  "new_facts": [],
  "reason": ""
}
```

**`relation`·`duplicate_of`·`evidence_chunk_ids` 셋은 아직 없다.** 앞의 둘은 벡터 중복 판정에,
마지막은 청크 인용에 쓰는 칸인데 본문 수집·청크·임베딩이 통째로 미구현이라 넣을 값이 없다.
지금 중복 판정을 하는 것은 LLM이 아니라 `modules/dedup.py`의 순수 규칙 둘이다(§6.4의 ①②).
셋을 붙이는 것은 청크·임베딩과 같은 묶음이다.

- 각 점수는 0~2다. 합계는 `value_score`에 저장만 하고 상태를 바꾸지 않는다.
- **`relevance`를 "직접 관련"으로 묻지 않는다.** 켜져 있는 피드 아홉 중 여섯이 비한국이고
  그것들을 모으는 이유가 전이 효과다. 한국을 언급하지 않는 연준 성명이 0점을 받으면
  아카이브의 대부분이 잘못 채점된다. 그래서 **경로의 존재와 길이**를 묻고, `reason`에 어떤
  경로인지(환율·금리·수요·공급망·투자심리) 밝히게 한다.
- **`instruments`와 `indicators`의 허용 값은 프롬프트에 후보 목록으로 제시한다.** 자유
  문자열을 받으면 조인이 안 되는 태그가 쌓인다. 수집기가 `EcosSeries`나
  `DomesticStock` Enum으로 식별자를 좁히는 것과 같은 이유다.
- **모르는 태그가 오면 그 값만 버리고 문서는 저장한다.** 태그 하나 때문에 문서를 잃지 않는다.
  버린 값은 로그에 남겨 마스터를 늘릴 근거로 쓴다.
- `duplicate_of`는 프롬프트에 넣은 후보 ID만 허용한다(미구현 — 위 참고).
- `direction`은 그 기사가 대상 종목·지표에 호재인지 악재인지다. 4단계에서 쓴다.

긴 보고서는 전체를 보내지 않는다. 제목·초록·목차·결론과 vector로 고른 핵심 청크만 평가한다.
**지금은 본문 자체가 없어**(`document.body`는 항상 `NULL`) 제목과 `summary`만 평가한다.

> **재계획 중, 유예(2026-08-26).** 이 절의 설계 대부분을 market-thesis가 이미 채웠다 —

> 답변은 등록된 근거 `ref`만 인용한다. 남은 것은 **카테고리 분석가 분할**과 재현 가능한
> 저장용 `market_report` 테이블 둘뿐이다. 브리핑 쪽은 Slack 메시지가 산출물의 전부라
> 저장용 리포트를 미뤄 뒀다. 착수 전에 market-thesis가 이 자리를 대신 채우고 있는지부터
> 판단한다.

무엇을 볼지 사람이 미리 정하지 않는다. "환율과 기술주"는 예시일 뿐이고, **가진 데이터로
무엇을 만들 수 있는지 LLM이 고르게 한다.** 다만 한 모델에게 전부 맡기지 않고 카테고리별
분석가로 나눈 뒤 종합한다.

### 8.1 카테고리 분석가와 종합 분석가

한 모델에게 모든 데이터를 주고 "알아서 판단하라"고 하지 않는다. **카테고리마다 분석가를
두고 각자 자기 영역만 보게 한 뒤, 그 관찰들을 모아 종합한다.**

| 분석가 | 영역 | 보이는 툴 |
| --- | --- | --- |
| `rates` | 6개국 국채 곡선, 단기 자금시장 금리 | `list_series`, `get_series`, `compare_series` |
| `fx` | 원/달러, 엔, 위안, 달러인덱스, 고시환율 | 〃 |
| `risk` | 지수·선물·VIX·반도체·원자재·암호화폐 | 〃 |
| `flow` | 종목별 투자자 순매수 | `get_investor_flow`, `get_series`, `list_series` |
| `news` | 기사·보도자료 | `search_documents` |
| **종합** | 위 다섯의 관찰 | 툴 없음 |

나누는 이유가 셋이다.

- **컨텍스트가 모자란다.** 금리 41계열, 가격 27계열, 환율 10계열, 수급, 기사 수백 건을 한
  번에 넣을 방법이 없다.
- **얕게 훑는다.** 볼 것이 많을수록 모델은 눈에 띄는 하나만 붙잡는다. 영역을 좁히면 그 안에서
  비교를 한다.
- **틀린 곳을 못 찾는다.** 결론이 하나로 뭉쳐 나오면 어느 근거가 틀렸는지 되짚을 수 없다.

**분석가는 결론을 내지 않는다.** "달러가 3주째 강세이고 20일 상관이 −0.6이다"까지가 분석가의
일이고, "그래서 반도체가 눌릴 것"은 종합의 일이다. 분석가마다 결론을 내면 종합 단계가
데이터가 아니라 문장 다섯 개를 중재하게 된다.

**카테고리마다 보이는 툴이 다르다.** 전부 보여 주면 각자 남의 영역을 뒤지고, 그러면 나눈 뜻이
없다. 카테고리를 늘리는 것은 `CATEGORIES`에 한 줄 더하는 일이지 코드를 복사하는 일이 아니다.

### 8.2 툴이 데이터를 준다

분석가는 프롬프트로 데이터를 받지 않는다. **무엇이 있는지 목록을 보고 필요한 것만 부른다.**
분봉 73만 행과 금리 20만 행을 프롬프트에 넣을 방법은 없다.

| 툴 | 하는 일 |
| --- | --- |
| `list_series` | 쓸 수 있는 시계열 목록. 좌표·라벨·종류·구간·**관측 수** |
| `get_series` | 시계열 하나의 일별 값 |
| `compare_series` | 두 시계열의 변화 상관과 **표본 수** |
| `search_documents` | 기간·태그로 문서. 제목·요약·점수만, 본문은 안 준다 |
| `get_investor_flow` | 종목 일별 투자자 순매수(수량) |

- **LLM에게 SQL을 주지 않는다.** 툴은 등록된 것만 있고 인자는 Pydantic이 검증한다. 자유 SQL은
  틀린 조인 하나가 그럴듯한 숫자로 리포트에 들어가고 사후에 가려낼 수 없다. 수집기들이
  식별자를 Enum으로 좁히는 것과 같은 판단이다.
- **툴 오류는 태스크 실패가 아니라 모델에게 돌려주는 값이다.** 없는 툴이나 안 맞는 인자는
  오류 문자열이 툴 결과로 돌아가고 모델이 고쳐서 다시 부른다. 우리 데이터는 아무것도
  만들어지지 않는다.
- **한 요청에 툴과 `response_format`을 함께 넣지 않는다.** 제공처마다 둘을 같이 줬을 때 동작이
  갈리고(스키마를 주면 툴을 안 부르거나 그 반대) 우리가 흡수할 방법이 없다. 조사 turn에는
  툴만, 답변 turn에는 스키마만 준다(`modules/llm.py`).
- **시계열은 좌표 하나로 부른다.** 금리·환율·지수·종목 종가가 서로 다른 테이블에 있어
  `daily_series` 뷰가 넷을 한 이름 공간으로 모은다. 좌표는 `provider:series_id`이고 문서 태깅
  프롬프트가 쓰는 표기와 같다.
- **금리는 변화폭, 가격·환율은 로그 수익률로 계산한다.** 국채 금리에 로그 수익률을 씌우면
  4.0에서 4.1로 오른 것과 0.4에서 0.5로 오른 것이 전혀 다른 크기가 되고, 유로 지역은 마이너스
  금리 구간이 있어 로그를 취할 수도 없다.
- **모든 툴에 행 상한이 있다.** 없으면 한 번의 호출이 컨텍스트 창을 통째로 먹는다.
- 툴 호출 수에도 상한을 둔다(`MAX_TOOL_CALLS`). 에이전트 루프가 아니라 한도가 있는 조사다.

### 8.3 우연한 상관을 거른다

조합을 수십 개 훑으면 그중 몇은 반드시 강한 상관으로 나온다. 데이터가 그렇게 생겨서가 아니라
많이 봤기 때문이다.

- `compare_series`는 **상관계수만 돌려주지 않는다.** 관측 수와 구간을 함께 주고, 표본이
  `MIN_MEANINGFUL_OBSERVATIONS` 미만이면 경고를 싣는다. 24일로 낸 0.9는 이야기가 아니라
  잡음이다. 숫자를 감추지는 않는다 — 표본이 짧다는 사실이 결론의 일부다.
- 분석가 프롬프트가 "경고가 오면 그 값을 근거로 쓰지 않는다"를 명시한다.
- 툴 호출 상한이 훑을 수 있는 조합 수를 막는다.

### 8.4 저장

`market_report`에 생성 시각, 대상 기간, 모델, 프롬프트 버전, **카테고리별 분석가 관찰 전체**,
종합 본문과 `claims`를 남긴다. 원천이 나중에 정정돼도 리포트가 본 값은 바뀌지 않도록 관찰을
그대로 복사해 둔다.

**분석가 관찰에 없던 숫자가 본문에 나오면 그 리포트는 버린다.** `unsupported_numbers`가 본문과
헤드라인의 숫자를 관찰의 수치·문장과 대조한다. 문자열 대조라 완벽하지 않지만, 모델이 데이터를
보지 않고도 그럴듯한 문장을 만드는 것을 막는 유일한 자동 검사다.

리포트를 저장하는 이유는 보관이 아니라 **채점**이다. 예측이 맞았는지 나중에 확인하려면
검증 가능한 형태의 주장이 남아야 한다. "기술주가 약할 수 있다"가 아니라 "향후 5거래일
005930 수익률이 음수 쪽"처럼 쓴다. 채점 자체는 이 문서의 범위 밖이지만, 채점이 가능한
형태로 저장하는 것은 범위 안이다.

## 9. 오류와 멱등성

- 시간 초과, HTTP 429, 5xx는 최대 3회 지수 백오프로 재시도한다.
- 인증 오류, 이용조건 위반, 파싱 계약 오류는 재시도하지 않는다.
- 출처별 작업은 격리한다. 한 출처의 실패가 다른 출처의 커밋을 되돌리지 않는다.
- LLM JSON 검증 실패는 오류를 포함해 한 번만 교정 요청한다. 두 번째도 실패하면 문서는
  태깅 없이 저장하고 다음 실행에서 다시 시도한다. **문서를 잃지 않는다.**
- 점수 범위나 후보 ID가 잘못되면 그 필드만 버린다.
- 같은 `content_hash`·모델·프롬프트 버전 조합은 다시 평가하지 않는다.
- **프롬프트 버전이 오르면 재평가 대상이 생긴다.** 재평가는 별도 DAG가 오래된 것부터
  배치로 돌린다. 이전본에는 이 경로가 없었다.
- 원본 저장이 성공하기 전에는 정규화 문서를 만들지 않는다.

## 10. 운영 지표

- 출처별 발견·수집·실패 문서 수, 마지막 정상 수집 시각
- 태깅 완료·미완료 문서 수와 가장 오래된 미완료 문서의 나이
- LLM 요청·실패·토큰 사용량과 **일 예산 대비 사용률**
- 중복 판정에서 규칙으로 끝난 비율과 LLM까지 간 비율
- 버려진 태그(마스터에 없는 종목·지표) 목록

별도 모니터링을 붙이지 않고 Airflow 로그와 PostgreSQL 집계, 기존 Grafana로 시작한다.

## 11. 검증

1. 같은 RSS fixture를 두 번 처리해도 문서 수가 늘지 않는다.
2. **같은 기사를 두 번 수집하면 `content_hash`가 같다.** 조회수·상대시각이 든 fixture로 건다.
3. 동일 본문은 대표 문서에 연결된다.
4. 코사인 0.95 이상과 0.80 미만은 LLM을 부르지 않는다.
5. 새 사실이 포함된 후속 문서는 `update`로 별도 저장된다.
6. 마스터에 없는 종목 태그가 오면 그 태그만 버리고 문서는 저장된다.
7. LLM JSON이 두 번 깨져도 문서는 태깅 없이 저장된다.
8. `metadata_only` 출처의 `body`가 `NULL`이 아니면 저장이 거부된다.
9. 한 출처가 실패해도 다른 출처 작업 결과는 커밋된다.
10. 한국어 문장이 `pdb.lindera('korean')` 인덱스로 검색된다(4단계 대비, ParadeDB 0.25.2 문법).
11. `document_instrument` 조인으로 종목별 기간 기사 목록이 나온다.
12. 관점을 바꾸면 `prompt_version`이 달라져 이미 평가한 문서가 재평가 대상이 된다.
13. 한국을 언급하지 않는 문서도 경로가 있으면 `relevance`가 0이 아니다(프롬프트 문구 고정).
14. 모르는 툴 이름이나 스키마에 없는 인자는 DB에 닿기 전에 거절된다(4단계).
15. 카테고리가 요청하는 툴이 전부 실제로 등록돼 있고, 등록된 툴은 전부 어느 카테고리엔가
    닿는다(4단계).
16. `news` 분석가는 가격 시계열 툴을 보지 못한다(4단계).
17. 분석가 관찰에 없던 숫자가 종합 본문에 나오면 검사에 걸린다(4단계).
18. strict 스키마의 모든 객체가 닫혀 있고 기본값이 있는 필드도 `required`에 들어간다.
19. 제공처가 스키마를 거절하면 스키마 없이 한 번 더 부르고 검증 경로로 떨어진다.
20. 툴 응답이 상한을 넘으면 잘려서 대화에 실린다.
21. 표본 수가 기준 미만이면 상관에 경고가 함께 실린다(4단계).

외부 HTTP와 LLM은 fixture와 가짜 응답으로 검사한다. PostgreSQL 확장·인덱스는 실제 테스트
DB에서 통합 검사 하나로 확인한다.

## 12. 2단계 완료 조건

- `requirements.txt`에 `openai`와 `langchain-text-splitters`가 있고 이미지가 그걸로 빌드된다.
- `LLM_BASE_URL`·`LLM_API_KEY`·모델 이름이 Airflow 환경에 설정돼 있다.
- 관점(`LLM_PERSPECTIVE`)이 `global`이고, 비한국 문서가 경로를 근거로 점수를 받는다.
- 공식기관 9곳과 확인된 언론이 1시간 주기로 등록돼 있다.
- 재실행해도 같은 문서가 늘지 않고 `content_hash`가 흔들리지 않는다.
- 모든 문서가 `source_record`로 추적되고 중복은 대표 문서에 연결된다.
- LLM 장애 중에도 수집이 계속되고 문서는 태깅 없이 저장된다.
- `document_instrument`와 `document_indicator`가 채워져 종목·지표로 기사를 뽑을 수 있다.
- 버려진 태그가 로그에 남아 마스터를 늘릴 근거가 된다.
