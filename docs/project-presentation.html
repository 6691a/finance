평가(LLM) 단계 · 재검증 로직 향상

LLM 답변을 바로 믿지 않습니다

평가 대상 조회미평가 또는 내용·프롬프트가 바뀐 문서
LLM 평가종목·지표, 방향, 0~8점, 새 사실과 이유
구조 검증JSON Schema와 Pydantic으로 타입·범위 확인
교정 1회형식 오류면 repair 지시를 붙여 재호출
독립 저장성공 문서는 커밋, 실패 문서는 다음 실행에서 재평가
현재 검증 방어선
제공처 Schema 강제지원하지 않으면 일반 응답으로 전환하되 내부 검증은 유지
형식·범위 검증JSON 구조, enum, 4개 점수 항목 각각 0~2(합계 0~8) 확인
도메인 검증마스터에 없는 태그와 툴이 주지 않은 근거 ref 제거
실패 격리문서별 결과·트랜잭션으로 한 건의 실패가 전체를 막지 않음
향상 방향

검증 이유 기록

어떤 규칙에서 탈락했는지 집계해 프롬프트 개선 근거로 사용합니다.

회귀 데이터셋

실패했던 실제 응답을 고정 사례로 남겨 같은 오류의 재발을 막습니다.

품질 지표

형식 실패율, repair 비율, 허용되지 않은 태그 비율을 추적합니다.

변경 시 재평가

문서 내용이나 프롬프트 버전이 바뀌면 평가 대상을 다시 선택합니다.

LangChain은 모델 호출 형식을 맞추고, LangGraph는 call → repair → call 같은 상태 흐름을 제어합니다.
